# 3x-ui Migration Manager — исправления v2.2 (кандидат)

Это **не опубликованная версия GitHub**. Пакет содержит три новых/заменяемых файла (`restore.sh`, `apply-nginx.sh`, `db_guard.py`) и `upgrade_manager.py`, который применяет их к **локальной копии** исходного репозитория, изменяет `setup.sh`, `menu.sh`, `backup.sh`, `adapt_db.py`, дописывает README и сохраняет оригиналы в `.pre-v2.2-...`.

## Что исправлено

1. SQLite — полный `integrity_check`, SQLite backup API для нормализации, отдельная адаптация и повторная проверка, атомарная установка под остановленной службой, сохранение старой базы и проверка после запуска.
2. Telegram — `tgBotEnable=false` только в копии для **нового** VPS; токен и настройки сохранены.
3. Nginx — ставится как пакет при необходимости **после подтверждения переноса**, конфигурация не активируется автоматически.
4. Nginx — при ручном применении `sites-enabled` считается источником действующей конфигурации (включая независимый файл), устраняются несогласованные копии в `sites-available`, проверяются размер, содержимое, `nginx -t`, `nginx -T`, наличие порта 443, предусмотрен откат.
5. Сбой `x-ui` больше не выдаёт успешный статус: после запуска проверяются состояние службы и SQLite.

## Применение к исходникам (не на работающем сервере)

```bash
# На тестовой машине (не запускайте restore.sh на рабочем VPS!)
git clone https://github.com/djekk9-ops/3XUI-MIGRATION.git
unzip 3xui-migration-v2.2-fix.zip -d /tmp
python3 /tmp/3xui-migration-v2.2-fix/upgrade_manager.py ./3XUI-MIGRATION
cd 3XUI-MIGRATION
bash -n restore.sh && bash -n apply-nginx.sh && bash -n setup.sh
python3 -m py_compile adapt_db.py db_guard.py
# Просмотрите git diff. НЕ коммитьте секреты и резервные копии.
git diff
```

Публикация изменений требует доступа к GitHub и отдельного подтверждения владельца. Для установки на новом **пустом** тестовом VPS после публикации: `setup.sh --repo ... --ref ... --no-run --update`.

**Нельзя** повторно запускать восстановление на `Pirogov2`, где уже есть 10 клиентов. Это опасно, и скрипт блокирует такой сценарий.

## Ограничения и план испытаний

- Доступа к реальному VPS и повторному end-to-end тесту в текущей среде нет. Изменения — кандидат, требующий проверки на отдельном чистом VPS.
- Для сертификата Let's Encrypt перенос файла не создаёт гарантии автоматического продления, пока DNS остаётся на старом VPS.
- При неуспешном запуске `x-ui` после переноса сохраните журнал: `journalctl -u x-ui -n 80 --no-pager`.
- Старый VPS и DNS не меняются данным пакетом.
